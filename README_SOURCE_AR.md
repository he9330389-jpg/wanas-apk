# WANAS — دليل ملفات المصدر والتشغيل

هذا المستودع يحتوي كود تطبيق WANAS الحالي المبني بـ Expo وReact Native وTypeScript، مع Expo Router وSupabase. النسخة المضغوطة لا تحتوي `.env` أو مجلد `.git` أو `node_modules` أو مخرجات البناء أو بيانات اعتماد خاصة.

## المتطلبات

- Node.js متوافق مع إصدار Expo الموجود في `package.json`.
- الوصول إلى مشروع Supabase الخاص بالتطبيق، أو مشروع Supabase بديل مع تطبيق الـ migrations وسياسات RLS المناسبة.
- تثبيت الحزم بالأمر `npm ci` اعتمادًا على `package-lock.json`.

## إعداد القيم العامة

1. انسخ `.env.example` إلى `.env`.
2. املأ `EXPO_PUBLIC_SUPABASE_URL` و`EXPO_PUBLIC_SUPABASE_ANON_KEY` بمعلومات **المفتاح العام anon/publishable فقط** للمشروع الذي تملك حق استخدامه. لا تضع `service_role` أو مفاتيح إدارة أو كلمات مرور أو رموز Expo داخل التطبيق أو GitHub.
3. أضف `EXPO_PUBLIC_GIPHY_API_KEY` إذا أردت تشغيل البحث عن GIF بمفتاح Giphy تملكه. مفتاح العميل يُضمّن في التطبيق ويمكن رؤيته في حزم الهاتف؛ استخدم قيود الحصة/النطاق لدى المزود ولا تضع فيه مفتاحًا سريًا.
4. قيم OAuth وواجهة API اختيارية بحسب الخدمات التي ربطتها؛ راجع التعليقات في `.env.example` و`app.config.ts`. احتفظ بأسرار الخادم في بيئة الخادم فقط ولا تضف بادئة `EXPO_PUBLIC_` إليها.

القيم الافتراضية المضمّنة في `app.config.ts` تشير إلى إعداد WANAS الحالي. غيّرها فقط إذا كنت تنقل التطبيق إلى مشروع تملكه أو لديك صلاحية عليه. البيانات الفعلية وقواعد الوصول تعتمد على Supabase وسياسات RLS، وليست مضمنة داخل ملف ZIP.

## تشغيل وفحص المشروع

- `npm ci` — تثبيت الاعتماديات حسب ملف القفل.
- `npm run dev` — تشغيل خادم API المحلي وMetro للمعاينة وفق سكربت المشروع.
- `npm run dev:server` — تشغيل API وحده على المنفذ المحدد في السكربت.
- `npm run dev:metro` — تشغيل Metro للويب على المنفذ المحدد في السكربت.
- `npm run check` — فحص TypeScript.
- `npm run lint` — فحص ESLint.
- `npm test` — تشغيل الاختبارات الموجودة.
- `npx expo-doctor` — فحص إعداد Expo.

يُنشأ مجلد Android/iOS عند الحاجة عبر أدوات Expo؛ لا يوجد مشروع Android مولّد يدويًا ضمن هذا الأرشيف. بناء APK حقيقي يحتاج بيانات اعتماد بناء صالحة وتشغيله عبر لوحة Expo/EAS المعتمدة للمشروع. لا تعتبر نجاح فحص الكود أو المعاينة بديلًا عن تثبيت التطبيق واختباره على هاتف فعلي.

## بنية المشروع

- `app/`: صفحات التطبيق ومسارات Expo Router.
- `components/`: مكونات الواجهة القابلة لإعادة الاستخدام، ومنها أدوات الرسائل والمرفقات.
- `lib/`: Supabase، الرفع، الترجمة، الإشعارات، التخزين المحلي الآمن وتفضيلات الرسائل.
- `supabase/migrations/`: تغييرات مخطط Supabase وسياسات RLS المضافة للمشروع.
- `server/`: نقاط API الخلفية.
- `drizzle/`: مخطط وأدوات قاعدة البيانات المستخدمة من الخادم.
- `assets/`: الصور والخطوط والأصول المضمّنة.
- `package-lock.json`: نسخ الاعتماديات المعتمدة.

## رفع المشروع إلى GitHub

بعد فك الضغط، أنشئ مستودعًا خاصًا أو عامًا حسب قرارك، ثم راجع `.gitignore` قبل أول `git add`. لا ترفع `.env` أو ملفات مفاتيح التوقيع أو ملفات الاعتماد أو أي رمز وصول. استخدم `.env.example` كقالب آمن، وأضف القيم الخاصة من إعدادات البيئة المحمية لدى مزود البناء.

## تنبيه أمني

أي كلمة مرور أو API key أو Expo token تم لصقه في محادثة عامة/غير مخصصة للأسرار يُفضّل إبطاله من لوحة الجهة المصدرة وإصدار بديل. لا تستخدم مفتاح OpenRouter/مزود النماذج كقيمة `EXPO_PUBLIC_` ولا تضعه في تطبيق الهاتف أو GitHub؛ استدعاء مزود النماذج يجب أن يمر عبر خادم موثوق إذا كان التطبيق يحتاجه.
