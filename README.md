# وَنَس — WANAS

تطبيق اجتماعي عربي يعمل على الويب وAndroid. البنية المقصودة فيها خدمتان فقط: **Supabase** للمصادقة وقاعدة البيانات وتخزين صور المنشورات، و**Vercel** لاستضافة واجهة الويب وendpoint فحص صحة بسيط. التطبيق المبني بـReact وCapacitor هو العميل الذي يتصل بهما، وليس خادمًا ثالثًا.

**تنبيه قبل الاستبدال:** هذا الأرشيف يضم `/api/health` فقط، ولا يضم أي Vercel API مخصص آخر. ميزات التطبيق تتصل بـSupabase مباشرة. إذا كان مشروع Vercel الحالي يحتوي endpoints إضافية تستخدمونها، خذ نسخة منها وادمجها قبل استبدال المستودع؛ لا أستطيع إعادة بناء كود API غير موجود في ZIP الأصلي.

## ما يعمل في هذه النسخة

- التسجيل بالبريد وكلمة المرور، تسجيل الدخول، واستعادة كلمة المرور عبر Supabase Auth.
- قراءة موجز المنشورات وفق صلاحيات RLS، ونشر نص أو صورة، وحذف منشوراتك.
- الإعجاب، التعليق، الحفظ، إعادة النشر، تعديل/حذف منشوراتك، ومشاركة رابط المنشور.
- البحث في أسماء المستخدمين، إرسال/قبول/رفض طلبات الصداقة، وعرض قائمة الأصدقاء.
- محادثات نصية وتنبيهات داخل التطبيق عند الإعجاب والتعليق وطلب الصداقة بعد تشغيل SQL التكميلي.
- تعديل اسم العرض والنبذة، وتسجيل الخروج وحذف الحساب.
- واجهة عربية RTL متجاوبة، مع بناء Android عبر Capacitor.

المراسلة هنا نصية مع تحديث دوري، وليست لحظية. القصص وإشعارات الدفع والفيديو ولوحة إشراف إدارية مستقلة ليست ضمن هذا الإصدار الأول. إعداد قوائم الخصوصية المخصصة والتحكم المتقدم بالتعليقات والأرشفة غير مكتمل. البلاغات تُسجّل في Supabase ويحتاج صاحب المشروع إلى مراجعتها من لوحة Supabase إلى أن تُبنى لوحة إدارة.

## 1. إعداد Supabase

استخدم مشروع Supabase الحالي. لا تنشئ مشروعًا جديدًا ولا تحذف الجداول أو البيانات الموجودة.

- إذا كانت جداول WANAS موجودة بالفعل، **لا تشغّل `supabase/schema.sql` مرة أخرى**. شغّل `supabase/production_hardening.sql` مرة واحدة من SQL Editor بعد مراجعة أثره. هو لا يحذف صفوف المستخدمين؛ لكنه يقيّد أعمدة الملفات الشخصية المكشوفة، ويوقف إدخال إشعارات مصطنعة من العميل، ويجهّز bucket خاصًا لصور المنشورات وسياسات الوصول.
- إذا كان المشروع فارغًا، شغّل `supabase/schema.sql` مرة واحدة أولًا، ثم `supabase/production_hardening.sql`.
- اختبر إنشاء حساب، نشر نص وصورة، الصلاحيات من حساب ثانٍ، الإعجاب والتعليق والصداقة والحفظ وحذف الحساب. لا تعتبر وجود الجداول وحده اختبارًا للسياسات.
- فعّل SMTP حقيقيًا في Supabase قبل تفعيل تأكيد البريد على المستخدمين. أضف رابط موقع Vercel إلى Authentication → URL Configuration → Site URL وRedirect URLs، ومنها رابط الواجهة العام المستخدم لاستعادة كلمة المرور.
- مفتاح التطبيق هو **publishable/anon public key** فقط. لا تستخدم `service_role` في `VITE_SUPABASE_ANON_KEY` أو في ملفات GitHub.

> ملاحظة مهمة: ملف `production_hardening.sql` يغيّر صلاحيات قراءة جدول `profiles` إلى أعمدة محددة. إذا كان لديك تطبيق آخر يعتمد على قراءة أعمدة أخرى من الجدول، راجعه قبل تطبيقه.

## 2. إعداد GitHub

ارفع محتويات هذا المجلد إلى المستودع، بما فيها المجلد المخفي `.github/workflows`. أضف من Settings → Secrets and variables → Actions → New repository secret:

| المتغير/Secret | القيمة |
|---|---|
| `VITE_SUPABASE_URL` | رابط مشروع Supabase، مثل `https://xxxx.supabase.co` |
| `VITE_SUPABASE_ANON_KEY` | publishable/anon key العام للمشروع |
| GitHub Variable `VITE_APP_URL` (اختياري) | رابط الواجهة العام؛ الافتراضي رابط Vercel الحالي |
| `ANDROID_KEYSTORE_BASE64` | ملف التوقيع `.jks` محوّل إلى Base64، للإصدار الموقّع |
| `ANDROID_KEYSTORE_PASSWORD` | كلمة مرور ملف التوقيع |
| `ANDROID_KEY_ALIAS` | alias المفتاح |
| `ANDROID_KEY_PASSWORD` | كلمة مرور المفتاح |

أضف أسرار التوقيع كلها معًا. إذا غاب ملف التوقيع، ينتج الـworkflow APK تجريبيًا (debug) **غير صالح للنشر كتحديث رسمي على Google Play**. لإنشاء مفتاح رفع جديد عند عدم وجود مفتاح سابق، استخدم جهازك المحلي واحفظ الملف وكلماته في مكانين آمنين:

```bash
keytool -genkeypair -v -keystore wanas-upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias wanas
base64 -w 0 wanas-upload.jks > wanas-upload.base64
```

ضع محتوى ملف Base64 في `ANDROID_KEYSTORE_BASE64`، والبيانات الأخرى في أسرارها المناظرة. لا ترفع ملف `.jks` أو ملف Base64 إلى GitHub. احتفظ بنسخة احتياطية آمنة من ملف `.jks` وكلمات مروره. لا تنشئ مفتاحًا جديدًا لكل إصدار؛ تحديث التطبيق المنشور يتطلب الاستمرار بمفتاح التوقيع نفسه. وإذا كان التطبيق سبق نشره، راجع package ID ونسخة Android ومفتاح الرفع الموجود قبل البناء.

## 3. إعداد Vercel

اربط مستودع GitHub في Vercel، واضبط Root Directory على جذر المشروع. أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` في Project Settings → Environment Variables لبيئات Production وPreview، ثم أعد النشر. ملف `vercel.json` يضبط إطار Vite ومجلد مخرجات البناء.

`/api/health` يفحص أن Vercel API يعمل فقط. التطبيق يتصل بـSupabase مباشرة عبر SDK وسياسات RLS؛ لا يرسل أسرارًا إلى Vercel Function.

## 4. التشغيل المحلي

```bash
cp .env.example .env.local
# عدّل القيم إلى بيانات مشروعك
npm ci  # يتطلب Node.js 22 أو أحدث
npm run dev
```

لا ترفع `.env.local` إلى GitHub. للتحقق من بناء الويب:

```bash
npm run build
npm run preview
```

## 5. متطلبات Google Play وبناء Android

هذه النسخة تستخدم Capacitor 8 وتستهدف Android 16 / API 36، وهو الحد الأدنى المطلوب للتطبيقات الجديدة والتحديثات في Google Play منذ 31 أغسطس 2026، بحسب [متطلبات Google Play الرسمية](https://support.google.com/googleplay/android-developer/answer/11926878)، وبإعداد Android موصى به في [دليل ترقية Capacitor 8](https://capacitorjs.com/docs/updating/8-0). راجع المتطلبات مجددًا وقت الإرسال لأنها قد تتغير.


أي push إلى `main` أو `master` يشغّل `.github/workflows/build-android.yml`. بعد نجاحه نزّل artifact باسم `wanas-android` من صفحة Actions. يحتوي APK؛ ومع أسرار توقيع صالحة ينتج أيضًا AAB.

- ثبّت APK الموقّع على جهاز اختبار أولًا.
- Google Play يستخدم عادة ملف AAB للتوزيع. ارفع AAB من Play Console، وأكمل بيانات المتجر وسياسة الخصوصية وتصنيف المحتوى وData safety وبيانات التواصل.
- راجع الحد الأدنى لمتطلبات Android وGoogle Play السارية وقت الإرسال؛ تتغير هذه المتطلبات بمرور الوقت.

## استبدال الملفات القديمة في GitHub

الطريقة الآمنة: نزّل نسخة احتياطية من المستودع القديم أولًا، ثم ارفع **محتويات** هذا المجلد بعد فك ZIP إلى المستودع نفسه، مع إظهار الملفات المخفية حتى لا يسقط مجلد `.github`. اترك ملفات `.env` و`.jks` خارج المستودع.

أو من جهازك بعد تنزيل وفك ZIP في مجلد جديد، وفي نسخة محلية من المستودع:

```bash
# تأكد أن المسار الحالي هو نسخة المستودع الصحيحة، وأن لديك نسخة احتياطية
find . -mindepth 1 -maxdepth 1 ! -name .git -exec rm -rf -- {} +
cp -a /path/to/wanas-release/. .
git add -A
git commit -m "Replace WANAS app source with release MVP"
git push origin main
```

الأمر الأول يحذف ملفات العمل المحلية داخل نسخة المستودع؛ لا تشغّله في مجلد غير صحيح. لا تحذف الجداول أو الصفوف من Supabase أثناء استبدال ملفات GitHub.

## قبل الإعلان الرسمي

استبدل بيانات التواصل في `public/privacy.html` و`public/terms.html`، وراجع النص القانوني وسياسة الاحتفاظ والحذف بحسب بلد التشغيل. اختبر نشر الصور والخصوصية بحسابات مختلفة، واختبر تسجيل الدخول وتأكيد البريد واستعادة كلمة المرور من Android بعد ضبط روابط Supabase. النشر إلى Google Play يحتاج حساب Play Console وإكمال مراجعاته وبيانات المتجر؛ وجود ملف APK وحده لا يعني أن التطبيق صار منشورًا أو معتمدًا.
